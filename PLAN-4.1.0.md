## 3. Naming convention

### 3.1 The principle

> **Directory = meaning. Suffix = readability.**

This is forced by the framework's existing globs, which are all
directory-based and extension-agnostic:

```ts
migrate-hooks.ts:57   discoverModuleFiles("**/database/models/*.{ts,js}")
routes.ts:11          discoverModuleFiles("**/routes/*.{ts,js}")
queue.ts:171          discoverModuleFiles("**/jobs/*.{ts,js}")
scheduler.ts:74       discoverModuleFiles("**/{schedules,console}/*.{ts,js}")
seed.ts:44            discoverModuleFiles(pattern)   // built dynamically
```

**Consequence: do NOT switch to suffix-based discovery** (e.g. `**/*.model.ts`).
It would break every existing module and contradict the design. Directory stays king.

Also: a user who writes `services/my.service.ts` must keep working — the glob is
`**/services/*`, so any filename inside `services/` is valid. The suffix is cosmetic.

### 3.2 The table

| Kind       | Directory (under `modules/<m>/`) | Suffix           | Primary file         |
| ---------- | -------------------------------- | ---------------- | -------------------- |
| route      | `routes/`                        | `.route.ts`      | `index.route.ts`     |
| controller | `controllers/`                   | `.controller.ts` | `auth.controller.ts` |
| schema     | `controllers/`                   | `.schema.ts`     | `auth.schema.ts`     |
| helper     | `controllers/`                   | `.helper.ts`     | `auth.helpers.ts`    |
| service    | `services/`                      | `.service.ts`    | `user.service.ts`    |
| middleware | `middlewares/`                   | `.middleware.ts` | `auth.middleware.ts` |
| model      | `database/models/`               | `.model.ts`      | `user.ts`            |
| seeder     | `database/seeders/`              | `.seed.ts`       | `user.ts`            |
| job        | `jobs/`                          | `.job.ts`        | `registeruser.ts`    |
| schedule   | `schedules/` or `console/`       | `.schedule.ts`   | `daily.ts`           |
| test       | `__tests__/`                     | `.test.ts`       | `auth.test.ts`       |
| **facade** | `facade.ts` (module root)        | —                | `facade.ts`          |

### 3.3 service vs helper — not the same

|             | Test                                     | Example                                                                     |
| ----------- | ---------------------------------------- | --------------------------------------------------------------------------- |
| **helper**  | pure computation, no I/O                 | `slugify("Hi There")` → `"hi-there"`<br>`hasRole(user, ["admin"])` → `true` |
| **service** | does something real — DB, files, network | `sendPasswordEmail(user)`<br>`createOrder(data)`                            |

> **helper = computes. service = does.**

### 3.4 `__tests__` is not new

`__tests__` already exists in maker-cli stubs. Keep it co-located per module
(`modules/<m>/__tests__/`). No new concept.

## 4. Facade rules

### 4.1 What it is

A per-module public API file. Mirrors `framework/facade.ts`, whose own docblock
already says _"App-layer imports should target this file."_

```ts
// src/modules/auth/facade.ts
export { hasRole, getCurrentUser } from "./controllers/auth.helpers.js";
export { createAuthSchema } from "./controllers/auth.schema.js";
```

Generated by default with `module:make`.

### 4.2 Usage

```ts
// ✅ other modules go through the door
import { hasRole } from "@/modules/auth/facade.js";

// ❌ reaching into internals — fragile, breaks on refactor
import { hasRole } from "@/modules/auth/controllers/auth.helpers.js";
```

### 4.3 The two rules

> **Rule 1 — Modules talk to each other ONLY through facades.**
> **Rule 2 — Facades NEVER import other facades.**

**Why rule 1 exists internally.** This is the exact bug fixed this session:
`config/session.ts` imported `config/index.js` while `config/index.ts` re-exported
session → cycle.

**Why rule 2 exists.** Facades re-export _everything_ in a module, so
`A/facade.ts → B/facade.ts → A/facade.ts` loops easily.

```
✅ WORKS
   A/facade.ts ──► B/helpers/tax.ts        (single file, NOT the facade)
   B/facade.ts ──► A/helpers/user.ts       (single file, NOT the facade)

❌ BREAKS
   A/facade.ts ──► B/facade.ts ──► A/facade.ts
```

**Escape hatch:** anything you want to share goes in the facade. If a facade
genuinely needs one file from another module, it imports that **single file**,
never the facade.

### 4.4 Inside vs outside a module

```
modules/auth/controllers/a.ts → modules/auth/controllers/b.ts   ✅ direct, same module
modules/admin/post/…         → modules/auth/facade.ts            ✅ through the door
modules/auth/facade.ts       → modules/auth/facade.ts             ❌ rule 1
modules/auth/facade.ts       → modules/billing/facade.ts          ❌ rule 2
```

## 5. Panels (`--path`)

### 5.1 A panel is only a folder separator

No `panel.ts`, no manifest, no marker file, no registry, no special lint rule.
Panels and normal modules follow **identical** rules.

```ts
module:make post --path=admin      →  src/modules/admin/post/
```

### 5.2 The one framework change

`discover.ts:42-43` currently takes only the first path segment:

```ts
export function moduleNameFromPath(filePath: string) {
  return path.relative(modulesPath, filePath).split(path.sep)[0]; // ❌ breaks on nesting
}
```

Change to `path.dirname(path.dirname(path.relative(modulesPath, filePath)))`:

```
auth/routes/index.route.ts       → "auth"       → /api/auth         (unchanged today)
admin/user/routes/index.route.ts → "admin/user" → /api/admin/user   (new)
admin/post/routes/index.route.ts → "admin/post" → /api/admin/post   (new)
```

Uniform for both. The `**/routes/*` glob already returns these paths — verified.

### 5.3 Scalar / OpenAPI separates panels for free

Routes already carry tags, and `RouteConfig` already has `tags?: string[]`.
Scalar groups operations by tag automatically.

```ts
// auth/routes/api.ts:30,43,56,66
tags: ["Auth"],
```

Stub derives the tag from the path:

```ts
admin/user/routes/index.route.ts  →  tags: ["Admin"]
admin/post/routes/index.route.ts  →  tags: ["Admin / Post"]
```

Scalar renders:

```
Auth
Admin ├─ Admin / Post
      └─ (user routes)
```

**Zero framework change** — only the stub. This is the real payoff of `--path`.

## 6. Circular import checker

### 6.1 Scope table

| Path                           | Policy       | Reason                                     |
| ------------------------------ | ------------ | ------------------------------------------ |
| `modules/**/database/models/*` | **exempt**   | Drizzle `relations()` needs mutual imports |
| `modules/**` everything else   | **error**    | controllers, services, routes, jobs        |
| `framework/**`                 | **enforced** | already cycle-free today                   |
| `resources/**` (frontend)      | **excluded** | React/Vue/Astro — anyone may change it     |

No per-module branching: the rule is _a cycle is allowed iff **every** file in it
is under `database/models/`_. A module with no models matches nothing, so
everything is checked — same code path.

### 6.2 Why models are exempt (not a workaround)

```ts
// user.ts:41
export const usersRelations = relations(users, ({ one }) => ({ roles, ... }));
// role.ts:12
export const rolesRelations = relations(roles, ({ many }) => ({ users, ... }));
```

`relations()` stores config **lazily** — cross-references sit inside arrow
callbacks that run at query time. Only the first argument is load-time, and ESM
resolves it. Any ban that doesn't exempt models breaks relational modelling.

### 6.3 Tool: dpdm (not madge, not Biome)

Measured in this repo:

|                           | madge                     | **dpdm**                                |
| ------------------------- | ------------------------- | --------------------------------------- |
| Added deps                | 13                        | 7 (incl. `typescript`, already present) |
| **Marginal install**      | 19.3 MB / 2251 files      | **7.6 MB / 672 files**                  |
| Detects `@/` alias cycles | yes                       | yes                                     |
| Type-only edges           | counted (false positives) | `--transform` drops them                |
| Models exemption          | custom post-filter        | `--skip-imports`, one line              |
| Scan time                 | ~400 ms                   | ~1000 ms                                |

**Biome is ruled out.** `noImportCycles` misses every `@/` alias cycle. The only
`paths` key in its schema belongs to `noRestrictedImports` (a rule option), not
module resolution. Confirmed empirically.

dpdm is not like Nest — static graph reader, zero runtime integration.

### 6.4 Dev-loop impact: none

```json
"dev": "node src/framework/maker-cli/index.mjs dev"
```

No cycle check runs during `dev`. Separate script, ~1 s, CI/pre-commit only.
**Production cost: zero.**

### 6.5 Files

`dpdm.config.cjs` — must be `.cjs`; dpdm's loader is CJS and rejects `.mjs`
(verified: `Error: Cannot find module 'file:///…dpdm.config.mjs'`).

```js
module.exports = {
  tsconfig: "tsconfig.json",
  transform: true, // drops type-only edges
  extensions: "ts,mjs",
  skipImports: ["(database[\\/]models[\\/].*):(.*)"], // models don't participate
};
```

`scripts/check-cycles.mjs` — needed because **dpdm's exit code is unreliable**
(returns 1 even with zero cycles, verified). Must inspect output, not `$?`:

```js
import { execFileSync } from "node:child_process";
const out = execFileSync(
  "dpdm",
  [
    "--config",
    "dpdm.config.cjs",
    "--no-progress",
    "--no-warning",
    "--circular",
    "src/**/*.{ts,mjs}",
  ],
  { encoding: "utf8" },
);
const bad = out.includes("Circular Dependencies");
console.log(bad ? out : "no circular dependencies");
process.exit(bad ? 1 : 0);
```

`package.json`: `"check:cycles": "node scripts/check-cycles.mjs"`

Biome stays untouched for lint/format. This is purely additive.

### 6.6 Distribution — who gets dpdm

**Verified chain — the template's devDependencies reach the developer's project:**

```
template/hono/package.json            (devDependencies today: 10, incl. biome/typescript/vitest)
        │  npm run sync:hono
        ▼
packages/create-nexwire/hono/package.json     ← already exists, already ships them
        │  npm create nexwire
        ▼
developer's project → npm install → dpdm installed
```

Evidence: `scripts/sync-template.mjs:29` skips only lockfiles
(`bun.lock`, `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`) — `package.json`
**is** copied. `packages/create-nexwire/package.json` has `files: ["src","hono","express"]`
and no devDependencies of its own.

**The checker must ship to developers**, because it guards _their_ modules:

| Where dpdm lives          | What it protects              | Useful?                      |
| ------------------------- | ----------------------------- | ---------------------------- |
| Monorepo root only        | the framework's own templates | ❌ no guardrail for app code |
| **Template `template/*`** | every scaffolded project      | ✅ **correct**               |

If it stayed in the monorepo, `post.controller.ts → user.service.ts →
post.controller.ts` in a user's project would go undetected — the exact bug class
this work targets.

**Cost per scaffolded project:**

```
dpdm   +7.6 MB / 672 files  (marginal — typescript is already a devDep)
       +1 devDependency
       +0 runtime cost (static analyzer, runs only on `npm run check:cycles`)
```

Compared with what a scaffold already installs: `@biomejs/biome` (73 MB),
`typescript`, `vitest`, `@vitest/coverage-v8`, `drizzle-kit`, `tsx`,
`tsc-alias`, 4× `@types/*`. dpdm is smaller than Biome alone.

**Decision — PENDING CONFIRMATION. Recommended: A.**

| Option   | dpdm in template | Script            | Effect                                  |
| -------- | ---------------- | ----------------- | --------------------------------------- |
| **A** ✅ | yes              | yes, documented   | guardrail available; wire into own CI   |
| B        | yes              | yes, undocumented | available but quiet                     |
| C        | no               | monorepo only     | templates clean, developers get nothing |
